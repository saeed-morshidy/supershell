# Changelog

## v0.1.0 — first release candidate (2026-11-08)

First public version of supershell.

### Added
- `supershell` CLI: `list`, `install`, `update`, `remove`, `uninstall`, `doctor`,
  `bench`, `mode`, `devops`, `icons`, `config`, `keys`, `restore`, `repair`,
  `--dry-run`.
- All Ubuntu packages installed in one apt call, with a single sudo prompt at the start.
- Transactional installs with automatic rollback, `repair` after interruption,
  timestamped backups and `restore`.
- Modules: `core` (Starship, fzf, zoxide, eza, bat, fd, ripgrep), `git` (delta),
  `editor` (Neovim 0.12 profile), `fonts` (DejaVu Sans Mono + Symbols Nerd Font
  fallback), `devops` (prompt context + lazy completions); optional `lazygit`,
  `helix`, `plus` (ble.sh + Atuin, local only), `tmux`.
- `classic` mode, `SUPERSHELL_DISABLE=1`, opt-in DevOps aliases.
- Dependency-free test suite (unit, integration, Arabic, performance), e2e script,
  GitHub Actions CI, 3-approval governance.

### Changed
- Downloads never hang: connect/speed/total timeouts, retries only for transient errors (not HTTP 404), distinct error messages; a file already in `~/.cache/supershell/dl/` (e.g. fetched with a browser) is reused and still checksum-verified.
- Editor plugin install: never leaves half-cloned plugins after a timeout, says it may take minutes, and is undone by a rollback.
- Init cache (`starship init` etc.) records which binary wrote it and is rebuilt when that changes; before, switching starship from apt to the release kept running the old binary (a release keeps its older build date).
- **supershell-theme**, supershell's own prompt theme and the new default: a full-width powerline bar, square ends, clock at the right, independent of starship presets (generated by `scripts/gen-supershell-theme.py`). Colours are palettes — `supershell` (a re-tuned pastel ramp, default), `supershell-root` (red, the default in root shells), `pastel`, `tokyo-night`, `catppuccin`, `gruvbox`, `nord`, `dracula`, `rose-pine`, `kanagawa` — via `supershell theme colors|root-colors <name>`; `supershell theme reset` restores the defaults. `supershell theme list` shows every palette drawn by starship as your real prompt; `theme colors` / `theme root-colors` without a name open a chooser with a live preview (fzf; numbered menu without a terminal).
- `font_fit` (default on): the Ptyxis font size is nudged to the nearest size at which the bar's arrows and rounded ends fill the line exactly on this screen (e.g. 14 → 14.5; measured at 96 dpi × text scaling, since GTK scales the display afterwards), using VTE's line-height formula through Pango (`lib/fontfit.py`). Found on the laptop: at 14 pt the rounded ends stopped one pixel above the bar's bottom edge.
- Default font: Cascadia Code NF (Ubuntu's fonts-cascadia-code): Arabic built in, and its powerline arrows, rounded ends and icons fill the cell height — with fonts that lack them, the rounded ends come from Symbols Nerd Font Mono and look too small (`doctor` says so). supershell-theme shows the system's icon first, right inside the rounded start (no gap), and a clock icon from the Nerd Font before the rounded end — the spacing of typecraft's starship prompt.
- supershell-theme moves its bar to two full-width lines when it does not fit on one (long folder, busy git status, narrow window): `starship-supershell-theme-split.toml` is rendered with the theme, and the shell measures each prompt and uses it only when needed (one extra starship run for those prompts only). With ble.sh the prompt is worked out again on resize/zoom, before ble.sh redraws it. Root shells (`supershell root on`) keep the one-line bar. `supershell theme split off` (`theme_split`) keeps every prompt on one line. The width check is plain string cuts (<1 ms; a first extglob version cost ~70 ms on every prompt).
- The rounded ends are drawn by supershell (`config/fonts/SupershellEnds.ttf`, generated by `scripts/gen-ends-font.py` with fontTools; reproducible bytes, checked by a test). The end's cell is printed in reverse video, so its background — the bar colour — is filled by the terminal to the exact cell edges, and the glyph cuts the two outside corners in the terminal's background colour, reaching past the line where VTE clips it. Font half-circles (U+E0B6/E0B4) stopped a pixel short at many sizes and at every zoom step. Works with any palette and terminal colours. Fonts other than Cascadia Code NF, DejaVu Sans Mono and Ubuntu Sans Mono get a note on `supershell font` (and in doctor) that a 1px step can show.
- supershell-theme has rounded ends by default (a half circle before the name and after the clock, at the window edge); `supershell theme ends square` for straight ones (`theme_ends`).
- The tools follow the theme palette (`theme_tools`, default on): an eza theme for `ll`/`la`/`lt` (with `LS_COLORS` from Ubuntu's default dircolors set aside for them), fzf colours, the closest bat theme (delta follows `BAT_THEME`; supershell's delta settings no longer fix `syntax-theme`). Written when the theme changes; start-up only reads a file. Your own eza theme, `~/.dircolors`, `EZA_COLORS`, `BAT_THEME` and `FZF_DEFAULT_OPTS` win.
- README rebuilt around real screenshots (`docs/images/`): starship, eza, git, bat, fzf and the CLI in a demo home, rendered by `scripts/screenshots/make.sh` (no personal data; regenerate after any visual change); `social-preview.png` for the repository card.
- `supershell -h` fits 80 columns, one option per line (tested).
- `supershell root on|off`: the same prompt in root shells, from root-owned copies only (never a file the user can change; `[custom]` modules refused; the starship init is printed by root's own binary in a clean environment, because `starship init` writes in the `starship` it finds on PATH — and is refused unless every starship it runs is root's copy). Changing the prompt or colours updates root's copy right away (sudo); `doctor` reports when it is outdated; `uninstall` removes it.
- Suggestions as you type (`plus`: ble.sh + Atuin) are now a default module; ble.sh comes only from Ubuntu's `ble.sh` package (no unverifiable download fallback).
- The CLI finds the tools it installed in `~/.local/bin` even when that folder is not on PATH yet (fresh servers, `su -c`, CI): prompt configs and editor plugins were silently skipped there.
- `doctor` never starts nvim before the editor plugins are installed (it made vim.pack download them).
- A downloaded archive is deleted only when the whole run succeeds; after a rollback, the (verified) file is reused.
- `doctor` no longer reports the icon font missing on systems with many fonts (SIGPIPE under `pipefail`).
- starship 1.27.0 pinned (apt ≥ 1.27, else the verified release).
- Default prompt is starship's own **pastel-powerline** preset, made two lines (`tokyo-night`, `gruvbox-rainbow` and the four `catppuccin-*` flavours also available).
- Presets are taken from the installed starship (never downloaded); supershell's extras (kubernetes context, command duration, exit status, git counts) are added on top by `lib/toml-merge.awk`, which never changes a preset value. `prompt_style = simple` keeps the minimal prompt; over SSH / in the console the plain prompt is used.
- First install asks for the prompt: **supershell** (default: pastel-powerline across the full terminal width with `$fill`, square at both ends, clock at the right; `prompt cap on` = the preset's rounded start) or **starship** (the preset exactly as published). Generated by `scripts/gen-custom-prompt.py` (glyphs written by code point). `--custom` / `--default` answer it; `supershell prompt custom on|off` changes it.
- Icons come from starship's `nerd-font-symbols` / `plain-text-symbols` presets instead of a hand-made list (`symbols.tsv` removed); `fallback-*.toml` covers only kubernetes/helm/terraform, which those presets lack.
- Git status in the prompt shows counts (`!3 ?1` = 3 modified, 1 untracked).
- `supershell prompt [<style>|edit|apply]` and `~/.config/supershell/prompt.toml`: your own prompt tweaks on top of any style (your values win), validated with starship before use; a file that adds problems is ignored with starship's message.
- New setting `font` (asked on the first install, `--font=NAME`, `supershell font <name>`): DejaVu Sans Mono (default), Cascadia Code, JetBrains Mono, Fira Code, IBM Plex Mono or Ubuntu Sans Mono, installed from Ubuntu's archive in the same apt batch. Arabic always comes from a fixed-width font and icons from Symbols Nerd Font Mono (`strong` fontconfig rules: with `weak`, other installed fonts such as Cascadia Code NF or the proportional DejaVu Sans won). supershell records the Ptyxis font it set and never changes one you picked yourself.
- New setting `font_size` (default 14) for the Ptyxis font the `fonts` module sets; `config set font_size N` applies it at once, but only while Ptyxis still uses the font supershell set.
- Neovim and the Symbols Nerd Font are now pinned in the manifest (GitHub asset digest / `SHA-256.txt`); `scripts/update-manifest.sh` cross-checks GitHub asset digests.
