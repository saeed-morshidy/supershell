# Configuration

## Settings

```bash
supershell config list
supershell config set <key> <value>
```

| Key | Values | Default | Meaning |
|---|---|---|---|
| `mode` | modern, classic | modern | `classic` = stock Bash (prompt, aliases, tools all off) |
| `icons` | auto, nerd, plain | auto | `auto` = Nerd Font icons when the font is installed and you're not on SSH |
| `devops` | on, off | on | k8s/docker/terraform info in the prompt + completions |
| `devops_aliases` | on, off | off | `k`, `d`, `dc`, `tf` |
| `plus_ble` | on, off | on | ble.sh when the `plus` module is installed |
| `plus_atuin` | on, off | on | Atuin when the `plus` module is installed |
| `set_editor` | on, off | on | set `EDITOR=nvim` if you haven't set `EDITOR` |
| `prompt_style` | pastel-powerline, tokyo-night, gruvbox-rainbow, catppuccin-mocha, catppuccin-macchiato, catppuccin-frappe, catppuccin-latte, simple | pastel-powerline | two-line prompts with coloured segments = starship's own presets (`catppuccin-*` = the catppuccin-powerline preset with that flavour's palette) + supershell's extras; need Nerd Font icons and fall back to `simple` over SSH / in the console |
| `prompt_custom` | on, off | on | supershell's ready-made settings for styles that have them (pastel-powerline: full terminal width, square ends, clock at the right); `off` = the preset as starship publishes it. Asked on the first install |
| `prompt_cap` | on, off | off | with the ready-made settings: the preset's rounded start of the line (`off` = square at the window edge) |
| `theme_ends` | rounded, square | rounded | supershell-theme: rounded ends of the bar, or straight at the window edges (`supershell theme ends …`). The rounded ends are supershell's own font (`Supershell Ends`, installed by the fonts module; `scripts/gen-ends-font.py`): printed in reverse video, the cell's background is the bar colour and the glyph cuts the corners in the terminal's background colour — exact at every size, zoom and palette. Drawn for Cascadia Code NF; also exact with DejaVu Sans Mono and Ubuntu Sans Mono; with the others a 1px step can show (`supershell font` and `doctor` say so) |
| `theme_tools` | on, off | on | eza (`ll`, `la`, `lt`), fzf, bat and delta take their colours from the theme palette; your own eza theme, `~/.dircolors`, `BAT_THEME` and `FZF_DEFAULT_OPTS` always win |
| `font` | cascadia-code, dejavu-sans-mono, jetbrains-mono, fira-code, ibm-plex-mono, ubuntu-sans-mono | cascadia-code | terminal font (`cascadia-code` = Cascadia Code NF: Arabic built in, powerline arrows and icons at full cell height; the bar's drawn rounded ends are made for its line) (Ubuntu package installed in the same apt batch). Fonts without Arabic take it from DejaVu Sans Mono, so Arabic stays fixed-width. Asked on the first install; `supershell font <name>` |
| `font_size` | 8–14, 16 | 14 | terminal font size the `fonts` module sets in Ptyxis (applied right away if supershell manages the Ptyxis font) |
| `font_fit` | on, off | on | set the terminal font a little larger or smaller (−1 … +1.5 pt) so the prompt bar's arrows fill the line exactly. VTE rounds the line height and draws these glyphs from the font, so at some sizes they end a pixel short. Measured at 96 dpi × text scaling (GTK scales the display afterwards). Zoom changes the size and is not covered; the rounded ends do not need this. Worked out with VTE's own formula (`lib/fontfit.py`, Pango); `doctor` tells you when the screen changed |

Changes take effect in new terminals, or after `exec bash`.

Environment overrides for a single shell:

```bash
SUPERSHELL_DISABLE=1 bash      # no supershell at all
SUPERSHELL_MODE=classic bash   # classic mode
```

## supershell-theme (the default prompt)

```bash
supershell theme                    # current colours
supershell theme list               # every palette, drawn as your real prompt
supershell theme colors             # choose while you look (arrows, Enter; Esc cancels)
supershell theme colors nord        # or by name: supershell, supershell-root, pastel,
                                    # tokyo-night, catppuccin, gruvbox, nord, dracula,
                                    # rose-pine, kanagawa
supershell theme root-colors        # root shells: supershell-root (red, the default),
                                    # same, or any — also with a live preview
supershell theme reset              # back to supershell-theme + default colours
```

supershell's own theme: a powerline bar across the full terminal width with rounded
ends (`supershell theme ends square` for straight ones), the clock at the right, extras (kubernetes, duration, exit status) in front of the
`❯`. It is a file in this repository (`config/starship/themes/`, generated by
`scripts/gen-supershell-theme.py`) and does not depend on any starship preset, so it
stays the same whatever starship ships. Colours are starship *palettes*: each one is
16 named colours (6 parts, their text, and 4 accents) that run as a smooth ramp from
part to part; switching is one setting. Root shells (`supershell root on`) use
`theme_root_colors` — red by default, so you see at once that you are root.
`theme reset` puts back the defaults and sets your `prompt.toml` aside (backed up).

**The tools follow the palette too** (`theme_tools`, on by default): `ll`/`la`/`lt` (an eza
theme in `~/.config/supershell/eza/`), fzf's colours, and the closest built-in bat
theme — which delta uses as well. The terminal's own palette (e.g. Ptyxis' colour
scheme) is left alone: it is your choice for every program. Your own settings always
win: `~/.config/eza/theme.yml`, `~/.dircolors`, `EZA_COLORS`, `BAT_THEME`,
`FZF_DEFAULT_OPTS`. `supershell config set theme_tools off` gives the tools their own
colours back.
The previews are drawn by starship itself with your fonts and icons, so they look
exactly like the prompt you get; the chooser uses fzf (installed with `core`) and
falls back to a numbered menu when there is no terminal.

## Customising the prompt

```bash
supershell prompt                 # current style + the list
supershell prompt catppuccin-mocha
supershell prompt custom on       # supershell's ready-made tweaks (off = the preset as published)
supershell prompt cap on          # …and keep the round cap at the start of the line
supershell prompt edit            # open your own tweaks file, apply when you close it
supershell prompt apply           # apply after editing the file another way
```

Three layers, each one winning over the one before:

1. **the style** — starship's own preset, exactly as starship publishes it, plus
   supershell's extras (kubernetes context, command duration, exit status, git
   counts) and always two lines;
2. **supershell's ready-made settings** (the default; `prompt custom off` skips them) —
   for pastel-powerline: the preset's own colours and arrows across the full terminal
   width (the last colour fills to the right edge with `$fill`), square at both ends,
   the clock at the right. `prompt cap on` adds the preset's rounded start.
   Generated by `scripts/gen-custom-prompt.py` (glyphs written by code point).
   They are plain starship settings in `config/starship/custom/`;
3. **your own tweaks** — `~/.config/supershell/prompt.toml`, below.

Your tweaks live in `~/.config/supershell/prompt.toml`, written with
[starship's settings](https://starship.rs/config/). They are applied on top of
**every** style and **your values win**; everything you don't set comes from the
style. supershell never writes to this file; `uninstall` keeps a copy in the backups.

```toml
[time]
disabled = true          # no clock

[directory]
truncation_length = 2    # only the last 2 folders
```

Before it is used, the merged prompt is checked by the real starship. If your file
adds a problem (e.g. `truncation_length = "two"`), it is **ignored** — your prompt
stays as it was — and `supershell prompt apply` and `supershell doctor` show
starship's message. Changing `format` replaces the style's whole layout.

## The prompt in root shells

```bash
supershell root on     # once, asks for sudo
supershell root off    # /root/.bashrc back exactly as it was
```

Root shells (`su -`, `sudo -i`, `sudo -s`) get the same prompt — and **only** the prompt
(no aliases, no ble.sh). A root shell must never read a file your normal account can
change (anything running as you could otherwise run code as root at the next
`sudo -i`), so `root on` copies, with sudo, into root-owned places:
`/etc/supershell/root/` (prompt configs, init) and `/usr/local/lib/supershell/starship`
when your starship is not already root-owned, then adds a marked block to
`/root/.bashrc`. Prompt configs that use starship `[custom]` modules are refused.
When the root prompt is on, changing your prompt or colours (`supershell theme …`,
`supershell prompt …`) updates root's copy right away (it asks for sudo); `doctor` tells you if it is ever out of date. `uninstall` removes it too.

## Customising the tools

Your own settings always win:

- **Prompt:** set `STARSHIP_CONFIG=~/my-starship.toml` in `~/.bashrc` *above* the
  supershell block. To change supershell's prompt for everyone, edit
  `config/starship/starship.toml.in` in the repo (simple style) or
  `config/starship/gruvbox-rainbow.overlay.toml` (additions to the gruvbox-rainbow
  preset; the preset itself comes from `starship preset gruvbox-rainbow`).
- **fzf:** set `FZF_DEFAULT_OPTS`, `FZF_DEFAULT_COMMAND`, `FZF_CTRL_T_OPTS` before
  the block; supershell only sets them when they are empty.
- **bat:** `BAT_THEME` is set to `ansi` only if empty.
- **Aliases:** if you define `ll`/`la` yourself (anything other than Ubuntu's
  stock definition), yours is kept.
- **Neovim:** if `~/.config/nvim` exists, `nvim` stays yours; the supershell profile
  is `snvim`. Edits you make to files in `~/.config/supershell-nvim` are never
  overwritten.
- **Git:** if you already set `core.pager`, delta is not enabled.
- **ble.sh:** `~/.blerc` is read after supershell's settings.
- **Atuin / Helix / tmux:** if you already have a config file, it is kept.

## Order inside `~/.bashrc`

The supershell block goes at the end. Lines *above* it are your settings and can
influence supershell (e.g. `STARSHIP_CONFIG`). Lines you add *below* it run after
supershell — fine for aliases, but don't put another prompt or `fzf`/`zoxide` init
there (`supershell doctor` warns about duplicates).
